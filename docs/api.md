# API reference

The API is served under `/api`. Interactive docs generated by FastAPI are at
`/docs` (Swagger UI) and `/redoc` when the API runs on its own port.

## Conventions

- **Auth:** `Authorization: Bearer <token>` from `/api/auth/login` or `/api/auth/signup`.
  Tokens are JWTs signed with `SECRET_KEY` and expire after `TOKEN_TTL_MINUTES`.
  `GET /api/invoices/{id}/pdf` also accepts `?token=` so plain links work.
- **Money** is a decimal string with two places (`"85.00"`), never a float.
- **Times** are ISO 8601 with a time zone (`2026-03-02T09:00:00Z`); naive
  datetimes are rejected. Dates are `YYYY-MM-DD`.
- **Durations** are integer seconds (`duration_seconds`, `tracked_seconds`...).
- **Errors** always look like:

  ```json
  { "error": { "code": "validation_failed", "message": "Some fields are invalid",
               "details": [{ "field": "hourly_rate", "message": "..." }] } }
  ```

  `401` not signed in, `404` not found (also for other users' records), `409`
  conflict (e.g. editing an invoiced entry), `422` validation, `429` too many
  login attempts (see `Retry-After`).
- Every response has an `X-Request-ID` header; send your own to correlate logs.

## Auth

| Method | Path                 | Body / notes                                  |
| ------ | -------------------- | --------------------------------------------- |
| POST   | `/api/auth/signup`   | `{email, password (8+), name}` -> token, user |
| POST   | `/api/auth/login`    | `{email, password}` -> token, user            |
| GET    | `/api/auth/me`       | current user                                  |
| POST   | `/api/auth/password` | `{current_password, new_password}` -> 204     |
| DELETE | `/api/auth/me`       | `{password}` -> 204, deletes all data         |

Signup and login are limited to 10 attempts per 5 minutes per client.

## Settings

`GET /api/settings`, `PATCH /api/settings` with any of: `name`, `timezone` (IANA
name), `rounding` (`none`, `6`, `15`), `currency`, `weekly_target_hours`,
`business_name`, `business_address`, `tax_id`, `payment_details`,
`invoice_prefix`, `payment_terms_days`, `default_taxes` (`[{name, rate}]`).

The time zone decides which day an entry belongs to in the timesheet. Rounding
rounds each entry *up* to the next increment when invoicing and valuing time;
tracked durations are never changed.

## Clients and projects

| Method | Path                            | Notes                                           |
| ------ | ------------------------------- | ----------------------------------------------- |
| GET    | `/api/clients`                  | `?include_archived=true`, `?q=` name or email   |
| POST   | `/api/clients`                  | `{name, email?, address?, currency, hourly_rate?, notes?}` |
| GET    | `/api/clients/{id}`             |                                                 |
| GET    | `/api/clients/{id}/summary`     | tracked/unbilled seconds, invoiced/paid/owed    |
| PATCH  | `/api/clients/{id}`             | partial update                                  |
| POST   | `/api/clients/{id}/archive`     | `/restore` to undo                              |
| DELETE | `/api/clients/{id}`             | 409 when the client has invoices                |
| GET    | `/api/projects`                 | `?client_id=`, `?include_archived=true`         |
| POST   | `/api/projects`                 | `{client_id, name, hourly_rate?, billable, color, budget_hours?}` |
| PATCH  | `/api/projects/{id}`            | `hourly_rate: null` falls back to the client    |
| POST   | `/api/projects/{id}/archive`    | also stops a timer running on it                |

Projects return `effective_rate` (own rate or the client's) and `used_seconds`.

## Time entries and timer

| Method | Path                             | Notes                                         |
| ------ | -------------------------------- | --------------------------------------------- |
| GET    | `/api/entries`                   | filters: `client_id`, `project_id`, `from`, `to`, `billable`, `q`; `page`, `page_size` (max 200) |
| GET    | `/api/entries/export.csv`        | same filters, CSV                             |
| POST   | `/api/entries`                   | `{project_id, started_at, ended_at, description?, billable?}` |
| PATCH  | `/api/entries/{id}`              | partial; 409 once the entry is invoiced       |
| DELETE | `/api/entries/{id}`              |                                               |
| POST   | `/api/entries/bulk`              | `{ids, action: billable \| non_billable \| delete}` |
| GET    | `/api/timer`                     | running entry or `null`                       |
| POST   | `/api/timer/start`               | `{project_id, description?, billable?}`; stops a running one |
| PATCH  | `/api/timer`                     | change description, project or billable       |
| POST   | `/api/timer/stop`                | optional `{ended_at}` for a forgotten timer   |
| POST   | `/api/timer/continue/{entry_id}` | new timer like an earlier entry               |

Entries are at most 24 hours long and must end after they start.

## Timesheet

- `GET /api/timesheet?week=YYYY-MM-DD` (any day of the week) returns
  `week_start`, `days`, `rows[{project_id, seconds[7], total}]`, `totals`, `total`.
- `PUT /api/timesheet/cell` `{project_id, date, minutes}` sets a day's total.
  Timer and manual entries are kept; the difference lives in one `grid` entry
  for the cell. You cannot go below tracked or invoiced time (422).

## Invoices

| Method | Path                                  | Notes                                   |
| ------ | ------------------------------------- | --------------------------------------- |
| GET    | `/api/invoices`                       | `status` (draft/sent/overdue/paid), `client_id`, `sort` (number/issue_date/due_date/total), `order` |
| GET    | `/api/invoices/overview`              | count and totals per status             |
| GET    | `/api/invoices/unbilled`              | `client_id, period_start, period_end` preview per project |
| POST   | `/api/invoices/generate`              | see below                               |
| GET    | `/api/invoices/{id}`                  | lines, taxes, totals                    |
| PATCH  | `/api/invoices/{id}`                  | drafts only: dates, notes, reference, taxes |
| POST   | `/api/invoices/{id}/lines`            | drafts: `{description, quantity, unit_price}` |
| DELETE | `/api/invoices/{id}/lines/{line_id}`  | drafts: only extra (non-time) lines     |
| POST   | `/api/invoices/{id}/send`             | draft -> sent                           |
| POST   | `/api/invoices/{id}/pay`              | sent -> paid, optional `{paid_on}`      |
| POST   | `/api/invoices/{id}/unpay`            | paid -> sent                            |
| POST   | `/api/invoices/{id}/revert`           | sent -> draft                           |
| DELETE | `/api/invoices/{id}`                  | drafts only; entries become unbilled    |
| GET    | `/api/invoices/{id}/pdf`              | PDF                                     |

`POST /api/invoices/generate`:

```json
{
  "client_id": 3,
  "period_start": "2026-07-01",
  "period_end": "2026-07-31",
  "project_ids": [7, 8],
  "group_by": "project",
  "issue_date": "2026-08-01",
  "due_days": 14,
  "reference": "PO-1234",
  "notes": "Thank you!",
  "taxes": [{ "name": "VAT", "rate": "19" }]
}
```

Only billable, stopped, not yet invoiced entries in the period are used. Each
entry is rounded with the user's rule, then grouped per project (or one line per
entry with `group_by: "entry"`). `taxes` omitted means "use the defaults from
settings"; `[]` means no taxes. Taxes are computed on the subtotal and rounded
half up to the cent.

Status `overdue` is derived: a sent invoice whose due date has passed.

## Reports and dashboard

- `GET /api/reports/time?from&to&group_by=client|project|month&client_id=`:
  tracked, billable and unbilled seconds and the billable value per currency.
  `/api/reports/time.csv` takes the same parameters.
- `GET /api/reports/revenue?year=2026`: invoiced (by issue date, drafts
  excluded) and paid (by payment date) per month and currency.
- `GET /api/dashboard`: today, this week, unbilled time and value, outstanding
  invoices and the latest entries.
- `GET /api/health`: `200 {"status": "ok", "database": "ok"}` or `503`.
